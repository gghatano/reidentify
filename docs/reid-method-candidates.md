# 再識別手法カタログ（安全性評価用）

匿名加工データの安全性評価のために、`reidentify` パッケージに実装する価値のある再識別手法の候補一覧。
攻撃の実演ではなく、**「この加工でどれだけ守れているか」を数値で示すこと**が目的。

- 対象: 本パッケージが扱う RAW / ANON 突合形式（`join_raw_anon_data` の出力）およびマスタ形式（`transform_transaction_to_master` の出力）
- 状態: 候補出し + 一次レビュー済み。実装着手前。

---

## 0. 前提となる評価フレーム

個別手法より先に、ここを直さないと成功率の数字が意味を持たない。

### 0.1 攻撃者知識モデルを明示する

「成功率 30%」は、攻撃者が何を知っている前提かを書かないと解釈できない。最低 3 段階を定義して、すべての実験でどれかを明記する。

| レベル | 攻撃者が持つ補助情報 | 対応する現実 |
|---|---|---|
| **W（弱）** | 準識別子の一部のみ（年代・性別・地域など数属性） | 公開統計・名簿からの推測 |
| **M（中）** | 準識別子一式 + 対象者の粗い行動特徴 | 別サービスの会員データを持つ事業者 |
| **S（強）** | RAW レコードそのもの（全属性・全履歴） | 元データ保有者、内部犯行、データ流出後 |

現行実装は暗黙に **S** を仮定している（RAW と ANON を総当たり結合し、全属性が見える）。S は上界としては正しいが、これだけだと「実際に起こりうるリスク」を過大評価する。W/M を回せるようにするのが実用上の要。

### 0.2 スコア層とマッチング層を分離する

現行は各 `reid_by_*` の中で「距離計算」と「最小値を取る」が一体化しており、手法を組み合わせられない。次の 3 層に割る。

```
[1] スコア層   score_*(dat_raw_anon, target, ...)
                → (RAW_ROW_NUMBER, ANON_ROW_NUMBER, SCORE) のロング形式
[2] 統合層     combine_scores(list(...), weights = ...)
                → 複数属性のスコアを 1 本に
[3] 割当層     match_greedy() / match_lsap() / match_margin(threshold)
                → (ANON_ROW_NUMBER, RAW_ROW_NUMBER, CONFIDENCE, RESULT)
```

これだけで「属性 5 個 × 距離定義 3 種 × 割当方式 3 種」が組合せで回せるようになる。以降の手法は原則 [1] のプラグインとして書ける。

### 0.3 評価指標を成功率だけにしない

| 指標 | 何が分かるか |
|---|---|
| **ベースライン成功率** | ランダム割当・最頻値割当での成功率。これを超えない攻撃は無意味。**必須** |
| 全体成功率 | 従来指標。攻撃者が全レコードに賭けた場合 |
| **精度–再現率曲線** | 攻撃者が「自信のあるものだけ」主張した場合。実際の攻撃者の動機に近い |
| **Top-k 命中率** | 候補 k 件まで絞れた割合。完全特定でなくても漏洩は起きる |
| **レコード別リスク** | 誰が危ないか。加工方針の改善に直結する（全体平均では見えない） |
| 最大リスク | 最も危険な 1 レコード。規制対応ではここが問われやすい |

## 1. 手法カタログ（22 件）

各項目: 概要 / 想定する攻撃者知識 / 必要な入力 / 実装メモ / 弱点。

### A. マッチング基盤（A1–A4）

#### A1. 多属性統合距離（重み付き / Mahalanobis）
- **概要**: 複数属性の距離を正規化して足し合わせる。属性間に相関がある場合は Mahalanobis 距離で共分散を考慮する。
- **攻撃者知識**: W / M / S いずれでも
- **入力**: 任意の複数属性
- **実装**: 各属性を z 化 or ランク化してから加重和。Mahalanobis は RAW 側の共分散行列を使う。
- **弱点**: 重みの決め方に恣意性が残る。→ B5 の IDF 重みか A4 の学習で決めるのが筋。
- **優先度**: **P0**。単属性攻撃しか無い現状の最大の穴。

#### A2. グローバル最適割当（線形割当 / ハンガリアン法）
- **概要**: 「ANON 1 件ごとに最も近い RAW を貪欲に選ぶ」のをやめ、**全体のコスト和を最小化する 1 対 1 割当**を解く。
- **攻撃者知識**: S（ANON と RAW が 1 対 1 対応する前提が要る）
- **実装**: `clue::solve_LSAP` または `RcppHungarian`。n が大きい場合はブロッキングで分割。
- **なぜ効くか**: 1 対 1 制約は強い事前情報。貪欲法だと 1 つの RAW が複数 ANON に重複して割り当たり、正解を取りこぼす。
- **弱点**: ANON がサンプリングされている（RAW の一部しか含まない）場合は前提が崩れ、逆に精度が落ちる。→ サンプリング率を引数に取り、ダミー行でパディングする実装が要る。
- **優先度**: **P0**。既存の全手法の割当層を差し替えるだけで成功率が上がるはず。上界の推定に適する。

#### A3. 信頼度付きマッチング（マージン / eccentricity）
- **概要**: 最良候補と 2 番手のスコア差（マージン）を信頼度とし、閾値を超えたものだけ「特定した」と主張する。Netflix 論文の eccentricity と同型。
- **攻撃者知識**: 全レベル
- **実装**: `(score_2nd - score_1st) / sd(scores)` を CONFIDENCE 列に持たせ、閾値を振って精度–再現率曲線を描く。
- **なぜ要るか**: 現実の攻撃者は全件を当てにいかない。「10% のレコードを 95% の精度で特定できる」方が「全件 30%」よりはるかに深刻で、現行指標ではこれが見えない。
- **優先度**: **P0**。

#### A4. 確率的レコードリンケージ（Fellegi–Sunter）
- **概要**: 属性ごとの一致確率 m（同一人物なら一致する確率）と u（別人でも偶然一致する確率）から尤度比を計算し、その対数和でスコアリング。m, u は EM で教師なし推定できる。
- **攻撃者知識**: M / S
- **実装**: R の `reclin2` / `fastLink` が実装済み。自前実装よりこれらへのブリッジを書く方が早い。
- **強み**: 重みが理論的に決まる（A1 の恣意性を解消）。統計局系の実務標準で、評価結果の説得力が高い。
- **弱点**: 属性の独立性を仮定する素朴版は相関のある属性で過信しやすい。
- **優先度**: P2（ただし外部パッケージ連携なら P1 に上げてよい）

### B. 希少性・情報量を使う（B5–B8）

#### B5. IDF 重み付き一致スコア
- **概要**: 属性値の一致を、その値の希少性で重み付けする（`w = 1 / log(出現頻度)`）。「東京都在住」の一致はほぼ無情報だが「特定の稀な購買品目」の一致は決定的。
- **攻撃者知識**: W / M / S（頻度は ANON 側から推定できるので追加知識不要）
- **実装**: 値の出現頻度表を作って join するだけ。軽い割に効果が大きい。
- **優先度**: **P1**。費用対効果が最も高い部類。

#### B6. Scoreboard-RH 型スコアリング（疎データ向け）
- **概要**: Narayanan & Shmatikov (2008) の Netflix 再識別手法。疎な高次元データ（購買履歴・視聴履歴）に対し、属性ごとの類似度を希少性で重み付けして合算し、eccentricity で判定。誤差・欠損に頑健なのが特徴。
- **攻撃者知識**: M（対象の履歴を一部知っていれば足りる。ここが恐ろしい点）
- **入力**: トランザクション形式、または DIST 列
- **実装**: B5 + A3 + 部分一致許容（値のずれを閾値内なら一致扱い）の組合せとして書ける。
- **弱点**: 密で低次元のデータには効かない。
- **優先度**: **P1**。トランザクションデータの安全性評価では中核。

#### B7. ユニシティ測定（p 属性で一意になる割合）
- **概要**: 攻撃ではなく**リスク上界の測定**。「ランダムに選んだ p 個の属性値を知っているとき、何 % の人が一意に定まるか」を p を振って曲線にする。de Montjoye らの unicity。
- **攻撃者知識**: 不要（データ構造だけで決まる）
- **実装**: 属性部分集合をサンプリングして group_by + 一意判定。素直に書ける。
- **価値**: 攻撃手法に依存しない上界なので、「うちの加工は手法 X には耐えた」という弱い主張を超えられる。加工方針の議論に直接使える。
- **優先度**: **P1**。実装が軽い割にレポート価値が高い。

#### B8. 最小ユニーク組合せの探索（SUDA 型）
- **概要**: 「この人を一意にしている属性の最小組合せ」を列挙する。どの属性を潰せばリスクが下がるかが分かる。
- **実装**: `sdcMicro::suda2` が実装済み。組合せ爆発するので属性数の上限管理が要る。
- **価値**: 対策の指針が直接出る唯一の手法。「年齢を 5 歳刻みにすればリスクが X% 下がる」が言える。
- **優先度**: P2

### C. 匿名加工の逆行（C9–C13）

日本の匿名加工情報で実際に使われる加工（一般化・抑止・ノイズ・スワップ・トップコーディング）を名指しで攻撃する群。**実務上いちばん重要だが、現行実装に完全に欠けている領域。**

#### C9. 一般化・区間整合マッチング
- **概要**: ANON 側が「30代」「東京都」のように一般化されている場合、数値距離は計算できない。代わりに**「RAW の値が ANON の区間・カテゴリに含まれるか」**で候補を絞り、含まれる候補数の逆数を情報量とする。
- **攻撃者知識**: W で十分（ここが要点。弱い攻撃者でも効く）
- **入力**: 一般化階層の定義（年齢 → 5歳刻み → 10歳刻み、市区町村 → 都道府県 → 地方）
- **実装**: 区間パースと包含判定。階層を YAML/CSV で外から与える設計にする。
- **優先度**: **P1**。実データの匿名加工情報を評価するなら必須。これが無いと現行パッケージは実務データに適用できない。

#### C10. 抑止パターン指紋
- **概要**: 「どのセルが `*`（抑止）になっているか」のパターン自体が識別子になる。抑止は稀な値に対して行われるため、抑止位置の組合せが特徴的になりやすい。
- **攻撃者知識**: W
- **実装**: 欠損位置をビットベクトル化し、その希少性を B5 と同様に重み付け。
- **弱点**: 一律抑止（全員同じ列を抑止）には効かない。裏を返すと「レコード依存の抑止は危ない」という知見が出る。
- **優先度**: P3（ただし発見的価値が高く、レポートのネタになる）

#### C11. ノイズ・丸めの逆算（MAP 推定）
- **概要**: 加工方式（ラプラス/ガウスノイズ、丸め幅）が既知または推定可能なとき、`P(ANON観測値 | RAW値)` を尤度として最大事後確率の RAW を選ぶ。距離ではなく尤度で解く。
- **攻撃者知識**: M / S + **加工方式の知識**（加工方針が公表される制度下では現実的な仮定）
- **実装**: ノイズ分布を引数で受け取り、対数尤度をスコア層に返す。
- **付随**: ノイズ幅自体を ANON の分散と RAW の分散の差から推定するサブ手法も作れる。
- **弱点**: 加工方式の仮定を外すと距離ベースより弱くなる。
- **優先度**: P2

#### C12. スワッピング検知（相関崩れの利用）
- **概要**: データスワッピングは属性間の相関を壊す。RAW で成り立つ相関構造から外れたレコードを「入替済み」と判定し、除外または復元してからマッチングする。
- **攻撃者知識**: M / S
- **実装**: RAW から回帰/共分散モデルを学習し、ANON 各行の残差を異常度とする。
- **優先度**: P3（研究寄りだが、スワッピングの安全性神話を検証する価値は大きい）

#### C13. トップコーディング・打ち切りの順序制約
- **概要**: 「年収 1000万以上」のように上限で丸められた値でも、**順序情報は残る**。順位ベースのマッチング（既存 `reid_by_num_rank`）と組み合わせ、打ち切り群の中では他属性で絞る。
- **実装**: 既存の rank 手法に打ち切り検知（同値が異常に多い上端）を足す。
- **優先度**: P3

### D. トランザクション・系列データ（D14–D18）

#### D14. 集合類似度（Jaccard / Tversky, min-hash）
- **概要**: 購買品目・訪問先などの集合属性に対し Jaccard 係数で照合。現行の DIST 列（`A:B:C`）は実質この集合表現なのに、L2 距離で扱っていて情報を捨てている。
- **攻撃者知識**: M（対象の行動の一部を知っていればよい）
- **実装**: `strsplit` → 集合化 → Jaccard。大規模時は min-hash + LSH（`textreuse`）でブロッキング。
- **優先度**: **P1**。現行 `reid_by_dist` の正しい置き換え先。

#### D15. 時空間ユニシティ（k 点特定）
- **概要**: de Montjoye ら「Unique in the Crowd」型。位置×時刻の点を k 個知っているだけで大半の個人が一意に定まることを示す測定。移動履歴・決済履歴で特に強い。
- **攻撃者知識**: W〜M（数点の観測のみ。SNS 投稿やレシートから得られる水準）
- **入力**: トランザクションに時刻・場所属性があること（現行のダミーデータ生成には無い → **要拡張**）
- **実装**: 点の粒度（時間解像度・空間解像度）を振って一意率を出す。粒度を粗くする効果が定量化できるのが利点。
- **優先度**: **P1**（該当データを扱うなら P0）

#### D16. 系列アラインメント（DTW / 系列編集距離）
- **概要**: 時系列の形状で照合。時刻のずらしやリサンプリングに頑健。
- **実装**: `dtw` パッケージ。O(n·m) なので候補絞り込みとの併用前提。
- **優先度**: P3

#### D17. 分布のロバスト比較（分位点ベクトル + Wasserstein）
- **概要**: 分布の照合を、分位点ベクトル（10 分位など）の距離、または Wasserstein 距離（EMD）で行う。長さの異なる分布を正しく比較できる。
- **実装**: `quantile()` で固定長ベクトル化 → L1/L2。EMD は `transport` パッケージ。
- **なぜ**: 現行の分布比較の実装上の欠陥（後述 2.1）を根本的に解消する差し替え先。
- **優先度**: **P1**（既存バグの修正を兼ねる）

#### D18. 活動プロファイル（件数・周期性）
- **概要**: レコード件数、曜日/時間帯の分布、活動期間の長さなど「量のプロファイル」で照合。単独では弱いが、A1 の一軸として強力。ROWCOUNT は既にマスタ形式で計算済みなのに未使用。
- **実装**: 既存の ROWCOUNT をスコア層に載せるだけ。
- **優先度**: P2（低コスト）

### E. 学習ベース・派生攻撃（E19–E22）

#### E19. 学習型リンケージ（ペア特徴 + GBDT）
- **概要**: 各 RAW×ANON ペアから特徴量（属性ごとの距離・一致フラグ・希少度）を作り、正解ラベルで二値分類器を学習。重みの最適化を機械に任せる。
- **攻撃者知識**: S + 一部の正解対応が既知（訓練用）
- **実装**: `lightgbm` / `xgboost`。ペア数が n² なのでネガティブサンプリング必須。
- **価値**: **達成可能な成功率の上界推定**として使う。手作りスコアがこれにどれだけ迫るかで、手法の完成度が測れる。
- **弱点**: 正解ラベルが要るので実際の攻撃者は使えない場面が多い。評価専用と位置づける。
- **優先度**: P2

#### E20. 埋め込み + 近傍探索
- **概要**: レコードをベクトル化して近似最近傍探索。大規模データでの現実的な攻撃経路。
- **優先度**: P3

#### E21. 属性推論攻撃
- **概要**: 個人を特定せずに、対象者の機微属性（病名・収入など）を当てる。「k-匿名だが同じグループ内が全員同じ病名」なら特定なしで漏洩する（l-多様性が扱う問題）。
- **なぜ要るか**: 再識別成功率 0% でも情報漏洩は起こりうる。再識別だけを見る評価は片手落ち。
- **優先度**: P2

#### E22. メンバシップ推論攻撃
- **概要**: 「対象者がこのデータセットに含まれているか」を当てる。特定に至らなくても、データセット自体が機微（患者名簿など）なら十分な被害。
- **優先度**: P3

## 2. レビュー結果

候補を出した後の見直しで挙がった論点。

### 2.1 現行実装に見つかった問題（手法選定に影響するもの）

1. **`calc_KL` が KL ダイバージェンスになっていない** — `R/reidentify.R:161,163` で最大値による正規化を行っているが、KL は確率分布（総和 1）を前提とする。総和正規化でなければ値の意味が定まらない。→ **D17 で置き換える**のが妥当。
2. **`distribution_distance` の長さ合わせが分布を歪める** — `R/reidentify.R:188-194` で短い側を平均値でパディングして `sort` している。件数の異なる 2 人の分布を比較する操作として正当化しにくく、パディング数自体（＝件数差）が距離に混入する。→ **D17 の分位点ベクトル化で解消**。なお「件数差」自体は D18 として独立の手がかりに格上げすべき情報であって、距離に紛れ込ませるべきではない。
3. **貪欲な argmin に 1 対 1 制約が無い** — 同一 RAW が複数 ANON に割り当たる。→ **A2**。
4. **タイブレークが `RAW_ROW_NUMBER[1]`** — 行順（＝多くの場合 ID 順）に依存する。ダミーデータでは ROW_NUMBER と ID が相関しているため、**成功率が実力より高く出る方向のバイアス**が入りうる。→ ランダムタイブレーク + 複数シードでの平均に変更。**評価の妥当性に関わるので優先して直す。**
5. **ベースラインが無い** — ランダム割当の成功率（1/n 程度）と比較しないと、得られた成功率が実力なのか偶然なのか判断できない。→ 0.3 の必須指標へ。

### 2.2 見送り・統合した案

- **単純ハッシュ照合の逆算（レインボーテーブル型）**: `openssl::md5` を import しているので ID のハッシュ化が想定されていると読める。「ID をハッシュ化しただけでは元が総当たりで復元される」のは事実だが、これは加工手法の是非であって再識別**手法**のカタログに置く粒度ではない。前提チェック（加工方式の妥当性検査）として別枠にする。
- **KL ダイバージェンス**: D17 に統合（上記 2.1-1）。
- **コサイン類似度**: B5（IDF 重み付き）とほぼ同じ挙動になるため独立項目にしない。
- **決定木ルールによる特定**: E19 に包含。
- **複数公開データセットの交差結合**: 手法というより攻撃シナリオ。0.1 の攻撃者知識モデル（レベル M の具体例）として扱う。

### 2.3 既存パッケージとの棲み分け

R には `sdcMicro` という統計的開示制御の標準パッケージがあり、個体リスク・SUDA・l-多様性などの**リスク指標**は既に実装済み。本パッケージの独自価値は**攻撃シミュレーションを回して実測の成功率を出す**側にあるので、

- リスク指標（B7, B8, E21）は `sdcMicro` に委譲するか、比較検証用に留める
- 攻撃実装（A, B5-B6, C, D）に注力する

という切り分けが妥当。既存実装との突き合わせは、こちらの実装が正しいことの検証にもなる。
