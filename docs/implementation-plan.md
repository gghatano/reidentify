## 段階 1: 評価フレームの再構築

### S1-1. スコア層 / 統合層 / 割当層への API 分離
- **背景**: 現行は各 `reid_by_*` の中で距離計算と argmin が一体化しており、手法を組み合わせられない。「属性 × 距離定義 × 割当方式」を掛け合わせるには 3 層に分離する必要がある。以降のほぼ全 Issue がこれに依存する。
- **実装スコープ**:
  - `score_*(dat_raw_anon, target, ...)` → `(RAW_ROW_NUMBER, ANON_ROW_NUMBER, SCORE)` のロング形式
  - `combine_scores(list_of_scores, weights)`
  - `match_greedy(scores)` → `(ANON_ROW_NUMBER, RAW_ROW_NUMBER, CONFIDENCE, RESULT)`
  - 既存 `reid_by_*` は新 API のラッパとして後方互換を維持
- **非スコープ**: 新しい距離定義の追加、新しい割当方式（S2-2）
- **依存**: S0-1, S0-7
- **優先度**: high
- **想定変更箇所**: `R/` 新規ファイル + 既存全関数
- **検証方法**: 既存 `reid_by_*` の返り値が修正前と一致（S0-3 のシード固定下で）
- **ラベル**: `type:refactor` `priority:high`
- **テンプレート**: refactor-task
- **PR 粒度**: 大きめだが分割すると中間状態が壊れるため 1 PR

### S1-2. 評価指標の拡充（ベースライン・精度–再現率・Top-k・レコード別リスク）
- **背景**: 現行 `reid_result` は success/trial の文字列のみ。ランダム割当のベースラインが無いため、得られた成功率が実力か偶然か判定できない。また攻撃者は全件を当てにいかないため、「一部を高精度で特定」が見えないと過小評価になる。
- **実装スコープ**: ベースライン成功率、精度–再現率曲線、Top-k 命中率、レコード別リスク、最大リスク。返り値を構造化オブジェクトに変更し `print` メソッドを用意。
- **非スコープ**: 可視化（プロット）
- **依存**: S1-1
- **優先度**: high
- **想定変更箇所**: `R/reidentify.R`(reid_result), 新規ファイル
- **検証方法**: 既知の正解対応を持つ合成データで各指標が手計算と一致
- **ラベル**: `type:implementation` `priority:high`
- **テンプレート**: implementation-task

### S1-3. 攻撃者知識モデル W / M / S の定義と実験設定への反映
- **背景**: 現行は RAW と ANON を総当たり結合しており、暗黙に「攻撃者が元データを丸ごと持つ」最強仮定（S）を置いている。上界としては正しいが、現実的なリスクは測れない。W（準識別子の一部）/ M（準識別子一式＋粗い行動特徴）/ S を選べるようにする。
- **実装スコープ**: 知識レベルを引数に取り、攻撃者が参照できる列を制限する仕組み。ダミーデータ生成側に準識別子の概念を追加。
- **非スコープ**: 個別手法の実装
- **依存**: S1-1
- **優先度**: medium
- **検証方法**: 同一データで W < M < S の順に成功率が単調増加すること
- **ラベル**: `type:implementation` `priority:medium`
- **テンプレート**: implementation-task

## 段階 2: マッチング基盤（P0 手法）

### S2-1. 多属性統合距離（重み付き / Mahalanobis）
- **背景**: 現行は単一属性でしか攻撃できない。現実の攻撃者は複数属性を併用するため、成功率を大幅に過小評価している。
- **実装スコープ**: 複数属性スコアの正規化と加重和、Mahalanobis 距離オプション（RAW 側共分散を使用）
- **非スコープ**: 重みの自動決定（S3-1 の IDF、または学習型で別途）
- **依存**: S1-1
- **優先度**: high
- **検証方法**: 単一属性より成功率が上回ること。相関を持たせた合成データで Mahalanobis が加重和を上回ること
- **ラベル**: `type:implementation` `priority:high`

### S2-2. グローバル最適割当（線形割当 / ハンガリアン法）
- **背景**: 現行の貪欲 argmin には 1 対 1 制約が無く、同一 RAW が複数 ANON に重複割当される。1 対 1 制約は強い事前情報で、上界推定に適する。
- **実装スコープ**: `clue::solve_LSAP` または `RcppHungarian` による割当層の追加。**ANON がサンプリングされている場合は 1 対 1 前提が崩れるため、サンプリング率引数とダミー行パディングを併せて実装する。**大規模時のブロッキング分割。
- **非スコープ**: 安定マッチング等の他方式
- **依存**: S1-1
- **優先度**: high
- **検証方法**: 貪欲法と成功率を比較。小規模データで総当たり最適解と一致すること
- **ラベル**: `type:implementation` `priority:high`

### S2-3. 信頼度付きマッチング（マージン / eccentricity）
- **背景**: 実際の攻撃者は全レコードを当てにいかない。「10% を 95% の精度で特定」の方が「全件 30%」より深刻だが、現行指標では見えない。
- **実装スコープ**: 1 位と 2 位のスコア差を正規化した CONFIDENCE 列、閾値による絞り込み、S1-2 の精度–再現率曲線との連携
- **依存**: S1-1, S1-2
- **優先度**: high
- **検証方法**: 閾値を上げると精度が単調に上がり再現率が下がること
- **ラベル**: `type:implementation` `priority:high`

## 段階 3: 手法追加（P1）

### S3-1. IDF 重み付き一致スコア
- **背景**: 属性値の一致は希少性で重みが変わる。「東京都在住」の一致はほぼ無情報、稀な値の一致は決定的。頻度は ANON 側から推定できるため追加の攻撃者知識を要さない。実装コストに対する効果が最も高い部類。
- **実装スコープ**: 値の出現頻度表と `w = 1/log(freq)` 重み、S2-1 への組み込み
- **依存**: S1-1, S2-1
- **優先度**: high
- **ラベル**: `type:implementation` `priority:high`

### S3-2. 集合類似度によるマッチング（Jaccard / min-hash）
- **背景**: DIST 列（`A:B:C`）は実質「集合」だが、現行は L2 距離で扱って情報を捨てている。購買品目・訪問先などの集合属性の正しい扱い。
- **実装スコープ**: 集合化 + Jaccard / Tversky、大規模時の min-hash + LSH ブロッキング
- **依存**: S1-1
- **優先度**: high
- **検証方法**: 現行 `reid_by_dist` と成功率を比較
- **ラベル**: `type:implementation` `priority:high`

### S3-3. 分布のロバスト比較（分位点ベクトル + Wasserstein）
- **背景**: S0-4 / S0-5 の根本的な解決先。長さの異なる分布を正当に比較できる。
- **実装スコープ**: 固定長分位点ベクトル化、Wasserstein 距離（`transport`）オプション
- **依存**: S0-5, S1-1
- **優先度**: high
- **ラベル**: `type:implementation` `priority:high`

### S3-4. 一般化・区間整合マッチングと一般化階層の外部定義
- **背景**: ANON が「30代」「東京都」のように一般化されている場合、数値距離が計算できない。**これが無いと実務の匿名加工情報にパッケージを適用できない。**弱い攻撃者（W）でも効く点でも重要。
- **実装スコープ**: 区間・カテゴリのパースと包含判定、候補数の逆数を情報量とするスコア、一般化階層を YAML/CSV で外部定義する仕組み
- **非スコープ**: 階層の自動推定
- **依存**: S1-1
- **優先度**: high
- **検証方法**: 一般化済み合成データで、包含判定により候補が正しく絞られること
- **ラベル**: `type:implementation` `priority:high`

### S3-5. ユニシティ測定（p 属性で一意になる割合）
- **背景**: 攻撃手法に依存しないリスク上界。「手法 X には耐えた」という弱い主張を超えられる。実装が軽い割にレポート価値が高い。
- **実装スコープ**: 属性部分集合をサンプリングし、p を振って一意率曲線を出す
- **依存**: なし（独立に実装可能）
- **優先度**: medium
- **ラベル**: `type:implementation` `priority:medium`

### S3-6. 活動プロファイルによるスコア（件数・周期性）
- **背景**: ROWCOUNT はマスタ形式で既に計算済みなのに使われていない。単独では弱いが S2-1 の一軸として有効。S0-5 で分布距離から切り離した「件数差」の正しい置き場。
- **依存**: S0-5, S2-1
- **優先度**: medium
- **ラベル**: `type:implementation` `priority:medium`

### S3-7. Scoreboard-RH 型スコアリング（疎データ向け）
- **背景**: Narayanan & Shmatikov (2008) の Netflix 再識別手法。攻撃者が対象の履歴を一部知るだけで成立する点が脅威。トランザクションデータ評価の中核。
- **実装スコープ**: S3-1(IDF) + S2-3(eccentricity) + 部分一致許容の組合せとして構成
- **依存**: S3-1, S2-3
- **優先度**: medium
- **ラベル**: `type:implementation` `priority:medium`

### S3-8. 時空間ユニシティ（k 点特定）
- **背景**: de Montjoye ら「Unique in the Crowd」型。数点の観測（SNS 投稿やレシートから得られる水準）で大半が一意に定まりうる。**現行のダミーデータ生成に時刻・場所属性が無いため、データ生成側の拡張が前提。**
- **実装スコープ**: ダミーデータへの時刻・場所属性追加、時間/空間の解像度を振った一意率測定
- **依存**: S1-3
- **優先度**: medium
- **検証方法**: 解像度を粗くすると一意率が単調に下がること
- **ラベル**: `type:implementation` `priority:medium`
